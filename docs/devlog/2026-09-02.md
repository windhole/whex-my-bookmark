## 07:16 〜 service worker が Cannot access before initialization で落ちる

### やったこと
- `void queueBootstrap()` が `let work` より前に走っていた TDZ を直し、キュー変数を先に初期化する

### 詰まった点・気づき
- Chrome は manifest 全体をエラー詳細に出す。実体は `Cannot access 'f' before initialization`（service worker registration failed, status 15）
- 以前は async の `bootstrap()` が最初の await で一旦戻るので、後段の `let` 初期化に間に合っていた

## 16:07 〜 manifest の suggested_key を外す

### やったこと
- `MacCtrl+Option+Command+1` は Chrome の suggested_key 制約（修飾キー最大2つ）で manifest 読み込みエラーになるため、`suggested_key` を削除
- ショートカットは `chrome://extensions/shortcuts` で手動設定する方針に README / ADR-0008 を更新

### 関連ADR / コミット
- ADR-0008

## 16:29 〜 起動直後からバッジに inbox 件数を出す

### やったこと
- service worker 読み込み直後に `refreshInboxBadge()` を呼ぶ（メニュー構築を待たない）
- bootstrap でも先にバッジ更新。保存はキューに入れ、成功時は `appendInbox` が返した件数を表示

### 詰まった点・気づき
- MV3 ではメニュー再構築より前に SW が起動完了しないと、バッジが空のまま残ることがある

## 16:34 〜 バッジが inbox の表示件数と一致しない

### やったこと
- バッジは storage 配列だけでなく、メニューと同じ merge 後の `# inbox` 配下の件数を数える
- storage の旧形式エントリ（`type` / `annotation` 欠落）を正規化して落とさない

### 詰まった点・気づき
- `# inbox` に書庫 Markdown のリンクがあると、メニュー上は inbox に見えるが storage 件数だけ数えると少なくなる
